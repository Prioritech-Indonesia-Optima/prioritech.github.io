# Plan: Dark-first aesthetic overhaul + unified mesmerizing 3D scrollytelling + ui-ux-pro-max bible

## Context
- User likes the 3D wireframe terrain but: (1) full-bleed orange light mode is an eye sore — "needs more black"; (2) frosted/blurred panels over the busy mesh look "fuzzy" — calm it down; (3) the scene should be impossible to click away from: pointer-reactive + click ripple + hypnotic idle animation; (4) scroll-storytelling should affect **all pages**, not just home; (5) install `ui-ux-pro-max` skill as the design bible for this repo; (6) add new open-source product **code.prioritech.co.id** (hero + nav highlight).
- Verified state: two duplicated raw-three.js engines — `components/three/TerrainScene.ts` (home, 5 scroll chapters) and `components/three/SubPageScene.tsx` (5 sub-pages, camera keyframes only). No pointer interaction, no reduced-motion/pause guards, theme sampled once at construction (toggle doesn't recolor live canvas), `computeVertexNormals()` every frame wasted (MeshBasicMaterial), per-frame `Vector3` allocations.
- Theme: `ThemeProvider.tsx` defaults to `prefers-color-scheme: light` → most visitors land on orange. `.light` in `app/globals.css:45-83` = `--background:#ef9a0e`. Frosted panels = `.text-backdrop` (`globals.css:258-265`, blur 6px) + ~20 `backdrop-blur-*` usages.
- Branch `brand-new-aesthetics`; untracked WIP from a sibling session (`frontend/components/graph/*`, `lib/graph-store.ts`, `components/home/CompanyProfile.tsx` — not imported by any committed page). Zero external links exist on the site today.
- `python3 3.13.11` available (required by the skill's search script). Skill repo already cloned at `/tmp/prioricode/ui-ux-pro-max-skill` (assets: `.claude/skills/ui-ux-pro-max/` = SKILL.md + data 3.1MB + scripts + references).

## Approach
Install the skill first so every subsequent design decision is checked against it (generate a persisted `design-system/prioritech/MASTER.md`). Then flip the site dark-first and de-frost the panels (cheap, high-impact). Then merge the two three.js engines into one config-driven `LatticeScene` used by all 6 pages, adding pointer attraction, a ripple-source pool, idle drift, live theme re-color, and perf/motion guards. Finally wire in code.prioritech.co.id. One engine + config objects beats patching two copies; analytic cursor projection (no raycaster) and CPU vertex math stay — at 110×110 grid with the wasted normal pass removed, the frame budget is fine.

### Phase 3: Unified LatticeScene engine — pointer ripple, idle hypnosis, all-page scrollytelling
- **Type:** creation + modification
- **Files:** create `frontend/components/three/LatticeScene.ts`, `frontend/components/three/sceneConfigs.ts`, `frontend/components/three/PageScene.tsx`; modify `frontend/app/page.tsx`, all five `app/*/​*Client.tsx`; delete `TerrainScene.ts`, `SubPageScene.tsx`
- **Changes:**
  - `LatticeScene.ts`: single imperative class merging both engines. Constructor takes `SceneConfig` from `sceneConfigs.ts`: `{ chapters: [{start,end,cameraPos,cameraTarget,terrainMode}], particles, gridRes }` — home keeps its 5 `CHAPTERS`/terrain modes; the 5 sub-pages' `PAGE_CONFIGS` camera paths (`SubPageScene.tsx:34-86`) are converted into the same chapter format (add `terrainMode` per page so every page morphs through distinct height fields — real scrollytelling, not just camera moves).
  - **Pointer reactivity:** `pointermove` (passive) → analytic ray-plane intersect at y=0 (no THREE.Raycaster) → stored cursor point; vertex loop adds Gaussian bulge `amp * exp(-d²/r²)` eased in/out. On touch devices the same works via drag; no hover assumption.
  - **Click ripple:** `pointerdown` pushes `{x,z,t0}` into a pool (max 8, oldest evicted); height contribution `sin(d*k − (t−t0)*ω) * e^(−(t−t0)*decay) * e^(−d*fall)` — a visible ring that races across the wireframe. Clicking is the hook: every click visibly moves the whole mesh.
  - **Idle mode:** after 4s without pointer/scroll input, blend in slow orbital camera drift (sin/cos offsets on chapter camera), stronger terrain "breathing" (time-driven traveling waves), and particle swirl; any input blends back out over ~1.5s.
  - **Live theme re-color:** `THEME = {dark:{fog,line,particle}, light:{...}}` constants matching Phase 2 tokens (dark: fog `0x0a0a0a`, gold `0xffc94a` lines; light: fog `0xf5f1e8`, ink `0x121212` lines); `MutationObserver` on `document.documentElement` class → mutate material colors/opacity/fog without rebuild.
  - **Guards:** remove `computeVertexNormals()` (`TerrainScene.ts:207` — unused by MeshBasicMaterial); reuse scratch `Vector3`s (`:181-182`); `visibilitychange` → pause/resume rAF; `matchMedia("(prefers-reduced-motion: reduce)")` → render one static frame, no loop; DPR cap 2 stays.
  - `PageScene.tsx`: `"use client"` wrapper (pattern of `ScrollScene.tsx:50-85`) — canvas `fixed inset-0 z-0 aria-hidden`, passive scroll → `setScroll`, dispose on unmount; scene built inside `useEffect` only (no SSR window access). Keep `SectionIndicator`/`ScrollProgress` exports in `ScrollScene.tsx` (move or re-export) since `app/page.tsx` imports them.
  - Swap mounts: `app/page.tsx:41` and each `*Client.tsx` (`AboutClient.tsx:35`, `DivisionsClient.tsx:63`, `ProjectsClient.tsx:77`, `TechClient.tsx:49`, `ContactClient.tsx:83`) → `<PageScene pageId="..." />`.
- **Dependencies:** Phase 2 (theme constants)
- **Success criterion:** all 6 pages show the wireframe scene; cursor drags a bulge; clicks send ripples; untouched scene visibly breathes/drifts; theme toggle recolors the live canvas without reload; 60fps on desktop.
- **Verification:** `npm run lint && npm run build`; dev server check each route, both themes, resize; `git rm` old files leaves zero imports (`grep -r "TerrainScene\|SubPageScene" frontend/app frontend/components`).
- **Risk:** sibling session may edit `app/page.tsx` (untracked graph WIP) / **Mitigation:** claim `frontend/app/page.tsx`, `frontend/app/globals.css`, `frontend/components/three/**` via sessions tool before editing; re-read files right before each edit.
